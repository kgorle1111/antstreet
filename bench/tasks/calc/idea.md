Create a Python module `calc.py` (standard library only) with one function:

    evaluate(expression: str) -> int | float

It evaluates an arithmetic expression given as a string. It must not use `eval`, `exec`, `compile`, the `ast` module, or anything else that hands the text to the Python interpreter; you write the tokenizer and parser yourself.

1. Numbers: a literal is one or more ASCII digits (0-9), optionally followed by `.` and one or more ASCII digits. `3`, `2.5`, `0.25` and `007` (value 7, leading zeros are fine) are literals. Literals are never negative; a minus sign is an operator (rule 4). `.5`, `5.`, `1.2.3` and `1..2` are invalid.
2. Binary operators are `+`, `-`, `*` and `/`, and `/` is true division. `*` and `/` bind tighter than `+` and `-`. All four are left-associative, so `10 - 4 - 3` is 3 and `100 / 10 / 5` is 2.0. Long chains must work: an expression of 2000 operands joined by `+` is valid and must not hit Python's recursion limit.
3. Parentheses group subexpressions and can be nested at least 50 levels deep.
4. `-` and `+` may also be used as unary operators in front of a literal, a parenthesised expression, or another unary operator, and can repeat (100 in a row must work): `-3`, `+3`, `--3` (is 3), `-(2 + 3)`, `2 * -3`, `2 - -3`, `+-+3` (is -3). A unary operator binds tighter than `*` and `/`.
5. Whitespace, meaning the characters space, tab, newline and carriage return, is allowed between any two tokens (and before the first and after the last) and is ignored. It is not allowed inside a literal: `1 2` is two literals in a row, which is invalid.
6. Result type: the result is an `int` when every literal in the expression is an integer literal (no `.`) and the expression contains no `/`; otherwise it is a `float`. A literal with a decimal point is a decimal literal even when its fractional part is zero (`2.0` gives a `float`), and the type is decided by the whole expression even when a decimal literal is multiplied by zero (`0 * 1.5` is `0.0`). `4 / 2` is `2.0`. Integer arithmetic is exact for arbitrarily large integers: `9007199254740993 + 0` is exactly 9007199254740993.
7. A division whose divisor evaluates to zero raises `ZeroDivisionError` (`1 / 0`, `1 / 0.0`, `0 / 0`, `1 / (2 - 2)`), even when the quotient would then be multiplied by zero (`0 * (1 / 0)`).
8. Malformed input raises `ValueError`. That covers: an empty or whitespace-only string; unbalanced parentheses (`(1 + 2`, `1 + 2)`); empty parentheses (`()`, `1 + ()`); a missing operand (`1 +`, `* 2`, `1 + * 2`, `/ 3`, `-`); two operands with no operator between them (`1 2`, `2 (3)`, `(1)(2)`, `(1) 2`; there is no implicit multiplication); an invalid literal (rule 1); and any character that is not a digit, `.`, `+`, `-`, `*`, `/`, `(`, `)` or the whitespace of rule 5. In particular there are no other operators (`**`, `//`, `%` and `^` are all invalid), no exponent or hex literals (`1e3`, `0x10` are invalid), no digit separators (`1_000` is invalid), no names or function calls (`abs(1)`, `pi`), and no non-ASCII digits.
9. Syntax is checked for the whole expression before anything is evaluated: an expression that is malformed raises `ValueError` even if an earlier part of it would divide by zero (`1 / 0 +` raises `ValueError`, not `ZeroDivisionError`).
10. A non-string argument (`None`, an int, a float, `bytes`, a list) raises `ValueError`, not `TypeError`.
